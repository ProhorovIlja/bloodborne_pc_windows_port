Date: 2026-11-12. Based on native V389 draft PR #119, V388 #118, V387 #117. **Original-free host pipeline only; NOT original-game independent boot.**

## Source-backed obstacle in pinned actual generator
Pinned `bloodborne-native/bloodborne-recomp` commit `8f31ec7c41f252730c6325d52647046baef7549f`, `tools/recomp/bbrecomp.c` (source-locked blob `f5032c9ead4988579e005af8a0a0ce4ba4ab66d8`): actual generated C function bodies emit `rc_ld`, `rc_st`, `rc_lds`, `rc_sts`, `rc_vld`, `rc_vst`, `rc_cas`. Pinned `src/recomp/rc.h` inlines route scalar accesses to `bb_load/bb_store`, which in `src/cpu/cpu_internal.h` treat the uint64 guest address as a raw native host pointer. The upstream vector helper uses `memcpy((void*)address)`; its CAS uses typed host pointers. Therefore prior V388/V389 VM tests did NOT prove actual generated AOT code obeyed leases.

A function may directly invoke other generated functions while using the same thread lease. V389 PAUSE refuses reconfiguration while this lease is held. ## Critical truth and safety boundaries
1. **This is a positive native source integration gate, not general original-game completeness.** V390 instruments specific known output helper names from a source-locked upstream generator, but does NOT prove arbitrary generated C has no direct guest host-pointer dereferences; source changes, unusual generator pathways, compiler builtins and inline assembly need further coverage. Real full original-game function corpus must be audited comprehensively, with generated source/assembly instrumentation/profiling and original retail code hashes tested by owner **privately**.
2. All source-generated `RcFn` entrypoints must be run WITH a V390 active thread lease, including callback/invasion/online job threads. An exception, `longjmp`, guest signal or non-local exit skipping `leave` will strand a pin, and raw pointer users bypass safety. Need RAII/SEH/setjmp handling and recovery in later steps.
