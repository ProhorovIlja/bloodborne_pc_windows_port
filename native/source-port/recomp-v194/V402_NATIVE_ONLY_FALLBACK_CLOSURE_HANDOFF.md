## Source-backed problem actually resolved

The genuinely pinned public `bloodborne-native/bloodborne-recomp` offline generator revision `8f31ec7c41f252730c6325d52647046baef7549f` emits several very different guest-runtime escape paths. `rc->step` executes an unsupported guest instruction in the interpreter; `rc->bail` resumes the rest of a function in the translator; `rc->tail` can delegate a tail call back to the host runtime. The generator emits `rc->bail` and `rc->tail` in the **generic end-of-function dispatch scaffold even for functions that otherwise contain only supported instructions**. V401 first discovered that its 12th synthetic probe (the invented `FS:[0x40]` read at 0x1140) emits `rc->step` and must not be compiled into a native-only executable. V402 avoids a false promise that simply removing the one `rc->step` path eliminates *all* fallback capability.
