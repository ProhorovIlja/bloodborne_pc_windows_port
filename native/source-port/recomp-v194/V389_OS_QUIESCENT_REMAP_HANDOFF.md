# Native V389 — quiescent guest VM pause + OS page remap/protection

Date: 2026-11-12. Based on V388 draft PR #118 and successful Windows/Linux source tests. Not a complete original Bloodborne native executable.

## What V389 actually implements
V386's `pins_and_closing` C11 atomic state now reserves a **PAUSED** bit (0x40000000) in addition to irreversible **CLOSING** (0x80000000), reducing maximum active pin count to 0x3FFFFFFF. `shyt_native_vm_pin_v386` rejects any paused or closing state; `unpin` masks only the actual count; close refuses to operate while paused and must be retried after a successful resume. This is important for avoiding a use-after-unmap while maintaining V382's already-published native AOT CALL/TAIL route.

New `native_os_vm_reconfigure_v389.{h,c}` exposes a **single control-thread** quiescent reconfiguration protocol:
- `pause` uses compare-exchange from pin-count ZERO to PAUSED atomically. It FAILS immediately if any active lease, already-paused, closing, or invalid owner state; no indefinite spin. New V386 pins are rejected during PAUSE.
- `reprotect` while paused updates real Windows VirtualProtect / Linux+macOS mprotect, and then guest V386 R/W/X permissions, while preserving W^X and NEVER making guest execution pages host executable.
- `remap` while paused allocates replacement OS pages (Windows VirtualAlloc, POSIX mmap), explicitly atomic-initializes each word from either zero or preserved old mapping values, applies OS permissions, then unmaps the old pages and switches owner/guest VM pointers at the same logical guest address/size. No active leased native call can hold a stale pointer under this contract.
- `map` while paused appends a new OS-allocated page-backed guest range and inserts it in sorted V386 guest address registry, preserving bounds/no-overlap/region count. `unmap` while paused removes an OS region, unmaps its backing and adjusts immutable-to-user but controller-modifiable metadata under pause.
- `resume` atomically changes PAUSED back to zero, admitting new guest VM pins again. Paused control operations may NOT race each other. Caller must serialize with any shutdown/cancellation control path and ensure ALL original/generated code accesses guest memory only through leases.

Tests in `test_native_os_vm_reconfigure_v389.c`: real OS page allocations, attempt to pause with an in-flight lease (also a held real POSIX worker thread pin), deny new pins while paused, forbid closing while paused, physically verify Windows PAGE_READONLY after reprotect and guest logical permission denial, remap content-preserving and zero-reset behavior without stale host pointers, add/remove a guest region and readd fresh initialized pages, invalid W^X/overlap/refused operations, verify V381/V382 native AOT CALL+TAIL still works after all remaps, reject after close and only release OS pages once join+quiescence conditions hold. No original Bloodborne data is used.

Cross-platform workflow `native-v389-quiescent-os-remap.yml`: GCC/Clang + ASan/UBSan Linux, Win64 clang-cl, Apple ARM64 host-only, with inherited V388 cross-word OS-backed VM and full pinned Windows RcApi V245/V384/V387 synthetic AOT plus 25 known imports to catch regressions. Real public upstream recomp ABI pinned to `8f31ec7c41f252730c6325d52647046baef7549f`.

## Strict boundaries
- PAUSE works only when the exact C11 V386 pin count is ZERO. It cannot protect any caller that bypasses V386 leases by using a raw host pointer in generated source, GPU/other threads or legacy imports. Full original-game source guest memory access must be adapted and proven before production dynamic remap.
- V389 remap changes the backing at the SAME guest base. Guest-address aliases/memory-mapped original files and dynamic loading are not implemented. Cross-region accesses and CPU x86 LOCK/atomic correctness are incomplete. V388 cross-word accesses are still two distinct atomics, not one transaction. OS page allocations do not prove real original game startup.
- All control methods require exactly ONE externally serialized owner/controller. Guest worker threads may try to acquire leases concurrently; PAUSE rejects when an active pin exists; do not call control methods from worker threads or concurrently with shutdown.
- No private original Bloodborne 1.09 game AOT full-function registry, owner-native game import closure, actual standalone Windows PE32+/Linux ELF64 game startup, renderer, audio, original saves/campaign/DLC/chalices or online/server/client/launcher has been achieved by this PR.
- Mac ARM64 host C11 tests are not an ARM64 original-game binary or Metal backend; Linux real native clock/import chain remains separate P0 work. V388 page-backed holder does not load PS4 eboot at runtime in synthetic tests, but does not demonstrate that a future whole-game binary needs no PS4 guest executable.
