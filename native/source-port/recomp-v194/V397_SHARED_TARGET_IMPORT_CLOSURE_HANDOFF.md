# Bloodborne Native V397 — multiple source-verified callsites sharing one native import

2026-11-12. Native source-port repository `ProhorovIlja/bloodborne_pc_windows_port`, based on Native V396 draft PR #126, V395 #125, V394 #124. This is NOT playable BBPort / BBSC Ultimate Yharnam Together and **not** an independently bootable original Bloodborne game.

## Evidence-backed motivation

V395/V396 used one sealed `ShytNativeImportSpecV395` per distinct target; exactly one continuation RIP could call each host service. That is appropriate for a bounded synthetic test but not realistic for ordinary host imports (many caller functions invoke the SAME library routine). Loosening the check to allow any return address would permit unverified guest code to enter sensitive host services. V397 instead retains exact **(guest target, generated continuation RIP)** authorization for every caller and checks the host service ABI is identical for a shared target.

## Strict limitations, no overclaims

- Exactly **SEVEN wholly invented x86-64 test functions** (compiled to C by the genuinely pinned public upstream `bbrecomp`) and THREE demo import service modes. This code has not analyzed all original Bloodborne 1.09 private AOT functions or its real import/prototype/ABI graph; no owner-private game code/assets/PS4 executables are put into GitHub Actions. Source+ELF object coverage is only a bounded compilation evidence gate, **not a proof of every possible original-game guest host-pointer bypass**.
- Multiple callers of the SAME target with the SAME service ABI are now supported; **different real import ABIs, native library callbacks, optional pointers, varargs, side effects or self-modifying guest modules need separately verified implementations**. Fixed 16 registered sites is insufficient for whole-game import closure: dynamic safe allocator and lifetime ownership or sealed scalable table design remains.
- V393 recovery applies only to explicitly requested trusted cooperative callbacks on the same thread. It does not handle raw arbitrary `longjmp`, signals, SEH, C++ exceptions, cancellation or crashes. A stranded V390 pin could block V389 page reconfiguration. x86 memory atomic cross-word and precise SIMD/page-fault semantics remain incomplete. Actual runnable game requires full native host operating-system service and graphics/renderers.
- No original game native Windows x64 PE32+/Linux ELF64 startup without PS4 EBOOT/runtime, renderer/D3D12/Vulkan/Metal, AI/physics/DLC/chalices/saves, shader streaming, gamepad/KBM controls/NG+/HUD or stable online LAN/P2P/server/client/launcher performance measured. Compatible playable BBPort/BBSC Ultimate track must stay separate. Do not claim zero latency or production performance from synthetic CI.
