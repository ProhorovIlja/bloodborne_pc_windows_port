# Bloodborne native V396 — source-pinned import callsite closure manifest

Date: 2026-11-12. Draft-native-source development, based on V395 PR #125. This is distinct from the playable compatibility BBPort and BBSC Yharnam Together Ultimate client/server/launcher project.

## Problem addressed and the actual change

V395 proved that seven invented x86-64 functions emitted by the real pinned `bloodborne-native/bloodborne-recomp` offline compiler could call a sealed V395 native host import list. However, authorization targets were hand-written in a C integration fixture and the compiled source/guest-return-site inventory wasn't tied to a separate, cryptographically identified original **source input**. A missing import callsite could therefore be silently left outside the allowlist until runtime, and no independent manifest held both generated callsite contracts.

V396 adds a verifiable **compile-time gate** tied to an independently declared manifest, and uses that attested manifest to populate an actual native host import route in tests. It does not falsely claim that the original commercial game source has been inventoried.

### Committed code

- `native_import_manifest_fixture_v396.json`: versioned, source-controlled, intentionally **invented-only** source fixture. Declares exact pinned public compiler revision `8f31ec7c41f252730c6325d52647046baef7549f`, SHA-256 of the invented build-time x86 ELF64 input `a87ec8ea0ede452e068c5d6529a88e0759e3738bec917c6624437e10051505af`, image base `0x400000`, all seven generated RcFunction offsets and **two source callsite contracts**. Function `f_10a0` generated `CALL RAX` returns to `0x4010a2` and has native host target `0x40009100` (the V395 guest-qword sum operation). Function `f_10c0` returns to `0x4010c2` and has its independently allowed native host target `0x40009400` (constant-return host service). Commercial game data and secrets are absent.
- `audit_import_closure_v396.py`: bounded Python local-only gate. Checks the **genuine source-locked public upstream generator** by SHA/revision, reads the input image incrementally and verifies SHA-256 against independently declared manifest, validates exact version/scope/schema/known import service and U64 addresses, enumerates **all** source-generated RcFunction declarations and direct native slots, checks generated C function bodies match, extracts every emitted `rc->call(..., B + 0x...ull)` continuation and rejects unknown call forms/interpreter STEP. Rejects missing, duplicated, extra, unowned or mismatched callsites and targets, and stale/extra/uninstrumented C shards. Reconstructs the original V390 guest-memory overlay byte-for-byte to ensure the native code paths use V386/V388 rather than raw host pointers.
- On success only, emits a **local generated C header** with the attested target, continuation RIP, fixed synthetic host service, and caller offsets. The C header is produced in the CI runner temporary directory, never loaded at game runtime. It supplies typed `ShytNativeImportSpecV395` definitions used by the V395 sealed import router. This creates a source-to-native-compiled-import chain without automatic generator-dependent allowlist inference.
- The tool supports `--scope owner-private` for **privately run** source/code audits on owner's actual licensed game (using owner-only image, generated C shards, and independently prepared full function/import manifest), but a private manifest must be available and run **only on owner-controlled infrastructure**. Nothing here authorizes uploading original game, decrypted files, generated retail game C, memory layouts or its SHA fingerprints to public CI/Drive. This mode is **not yet tested against Bloodborne 1.09**. It cannot establish dynamic indirect target set closure merely from `CALL RAX` source; only the declared exact target pairs are permitted at runtime.
- `test_audit_import_closure_v396.py`: positive and negative source/model tests. Rejects image hash drift, one missing function, partial callsites, wrong return offset, duplicate target, callsite assigned to wrong source function, missing table body, `rc->step`, an unsupported dynamic next address, altered function body and altered/duplicate manifest, bad scope, unknown import type and malformed addresses.
- `test_native_import_closure_v396.c`: compiles and executes **actual pinned bbrecomp-generated C** from seven wholly invented x86 machine-code functions. First confirms that the generated import header matches the manually checked synthetic RDI/RSI/RDX qword sum service. Registers the second exact target/continuation from the attested header and proves the **second** genuinely generated `CALL RAX` can now execute its own authorized service successfully (rather than only being refused for incorrect continuation as in V395). Retains all V395 negative unknown-target, mismatched-next-site and guest read-only/unmapped tests, byte-safe recovery, V389 OS page remap, V390 C11 memory lease and V393 trusted callback recovery, including nested source-generated code and LOCK/CAS/SSE/AVX correctness for the invented fixture. The generated import header is passed into the test compile via runner-temp include path.
- `.github/workflows/native-v396-source-manifest-closure.yml`: builds the genuine public pinned offline bbrecomp compiler, creates invented test ELF at build time only, emits real generated C shard and V390 overlay, runs V392 full-shard and V395 compiled-ELF provenance checks, then V396 manifest-negative suite and SHA256 identity + full callsite attestation. A prevalidated generated C header is used to compile genuine functions into a native Linux binary under both GCC and Clang and separate ASan/UBSan, a native Windows PE32+ under clang-cl with `/W4 /WX` host bridge, and host-only macOS ARM64 when runner availability permits. Commercial game assets/SDKs/keys never appear in public workflow inputs.

### Production limitations

- **This still does not compile or independently boot original Bloodborne 1.09.** It compiles **seven invented functions** only. The manifest gate proves full **declared** synthetic function/site coverage, not complete original-game indirect target closure, all host imports or source-generated codegen parity. A static `CALL RAX` may compute a dynamic target; the compile-time checker cannot prove which targets the game will use. V395's runtime whitelist will refuse any target/next not explicitly declared, which is correct fail-closed behavior but insufficient for full original game.
- V396 manifest requires each approved guest target be used at only one guest continuation because V395's current route table indexes unique targets. Real original system functions naturally have multiple callers; a later verified multi-callsite shared-target authorization model will be required, preserving a source-attested set of allowed (target, next) pairs. Do not silently relax the seal/return-site restrictions.
- V392 whole generated-shard C and V393/V395 ELF symbol/relocation audits do not prove no inlined raw host guest pointers or unsupported library calls in a huge original code corpus. Real original 1.09 owner's licensed AOT and original function/ABI imports remain unscanned in public CI.
- V393 host recovery is **only trusted cooperative synchronous same-thread callback**, not arbitrary POSIX signals, `SIGSEGV`, Win32 SEH, raw `longjmp`, C++ exception or task cancellation. V390/V389 lease safety outside these trusted paths isn't proven.
- C11 seq_cst guest `LOCK` CAS crossing two uint64 backing words still intentionally aborts; actual x86 memory aliasing, faults, I/O, SIMD atomicity and native guest VM multicore memory parity remain incomplete.
- No original Windows x64 PE32+ or Linux ELF64 fully independent game executable, startup trace without PS4 runtime, native game renderer D3D12/Vulkan, shader/asset streaming, CPU/GPU physics/AI/save/DLC/chalices/gameplay, PC KBM/controller settings/NG+, or real LAN/P2P/dedicated online/client/server/launcher performance demonstrated. Apple ARM64 host test is not original-game ARM64 recompilation.
