# Native V375 — FLVER2 skeleton hierarchy and bind pose; independent-game AOT gap audit

Date: 2026-11-12. Branch: `feature/native-v375-flver-bind-pose-20261112`, stacked on V374.

## Outcome and evidence boundaries

This is an independently authored **C11** FLVER2 bone graph and local/world bind-pose transform component. It runs on native Windows and Linux with no EBOOT, PS4 kernel, HLE, Wine, Proton, shader translator, runtime game data, or external dynamic allocator. It is an **asset decoding component**, not a complete Bloodborne game or a skinned renderer.

Public tests use only invented FLVER2 data. Original user-private Bloodborne/DS3 FLVER2 models are analyzed **separately** and never copied to public GitHub, Actions, user-facing releases or this text file. Private original game files and saves remain unchanged. No production Fornex or network deployment has been attempted.

### Implemented source

- `native/source-port/recomp-v194/native_flver2_bind_pose_v375.h/.c` — validates the **whole** FLVER2 0x20013/0x20014 via V362 and reads the fixed 128-byte FLVER bone records. Bounds-checks bone count (max 2,048), UTF-16LE terminated bone-name offsets, finite translation/rotation/scale, valid parent/child/next/previous links and reciprocal sibling links. Detects parent cycles and orphaned child nodes by traversing each parent's child list.
- Computes, in caller-owned arrays, row-vector **local = scale × rotationX × rotationZ × rotationY × translation** and **world = local × parent_world**. Handles parents stored **after** their children by processing by increasing hierarchy depth. Matrix elements must remain finite. Errors must not yield usable matrices; overflow during matrix generation clears outputs. No heap allocation, global state, disk/network operations, guest execution or original-game shader code.
- `test_native_flver2_bind_pose_v375.c` — fabricated three-bone hierarchy, true matrix translation tests (90° Z then X+Y with nonuniform scale), depth traversal, parent-after-child, reciprocal sibling and root links, bad names, cycles, NaN, out-of-range parent, orphan, output overlap, too-small storage, empty skeleton. Only synthetic input files generated by the test itself.
- `.github/workflows/native-v375-flver-bind-pose.yml` — Ubuntu 24.04 GCC/Clang, Clang ASan/UBSan; Windows 2022 clang-cl C11. Public test builds do not mount CUSA03173 or DS3.

Public CI: https://github.com/ProhorovIlja/bloodborne_pc_windows_port/actions/runs/43180079740 — **Windows and Linux green on the final V375 source and strengthened matrix tests**. The earlier base run also passed: https://github.com/ProhorovIlja/bloodborne_pc_windows_port/actions/runs/43179851540.

### What V375 does NOT do

FLVER bind pose alone is **not actual animation**. No skeleton inverse bind matrices, HKX animation curves, dual quaternions, matrix palette upload, morphs, physics/cloth, bone naming resolution against external skeleton tables, interpolation, topology-dependent skinning or full renderer integration. The world matrices are **row-major for row-vector transforms**, not column-major OpenGL/Vulkan shader matrices; a GPU shader must explicitly transpose or use matching algebra. V375 does not change V370–V373 material/vertex/index draw smoke, networking, or loading original executable code. If a model's hierarchy varies from the supported subset, fail closed; do not invent relationships or bone transforms.

## New GitHub research beyond V374: prioritize complete native game closure

Public third-party projects were inspected through GitHub source and current documentation, with no code automatically merged:

1. [`JKAnderson/SoulsFormats/SoulsFormats/Formats/FLVER/Bone.cs`](https://github.com/JKAnderson/SoulsFormats/blob/master/SoulsFormats/Formats/FLVER/Bone.cs): 128-byte FLVER bone record; Euler X-Z-Y local rotation and hierarchy link semantics. Our C code is independently authored (GPL license compatibility/source provenance assessed before any future code import).
2. [`bloodborne-native/bloodborne-recomp`](https://github.com/bloodborne-native/bloodborne-recomp), [`docs/RECOMPILATION.md`](https://github.com/bloodborne-native/bloodborne-recomp/blob/main/docs/RECOMPILATION.md): roughly **10,284,725 / 10,691,122 instructions** compiled (96.2%), **181,521 / 181,570 functions** recompiled, yet only about **933 / 179,698 functions** checked call-by-call in replay (2026-11-02 snapshot). Some paths still fall back to runtime translator, notably import stubs, `setjmp` and patched/live-generated code. These numbers measure that project's work — **not our public source branch** and not a proof that a no-guest-code Windows/Linux game exists.
3. [`bloodborne-native/bloodborne-runtime`](https://github.com/bloodborne-native/bloodborne-runtime): explicitly describes what must be **removed** to reach our stricter target. Currently starts by loading/patching the PS4 executable; serves PS4 system calls (threads/memory/files/saves/pad/audio/network); and translates GPU commands, shader data and memory usage. Its native Mac Metal backend is an improvement in final GPU API choice but **still reads PS4 graphics commands**. The independent native port cannot depend on these translation layers at runtime.
4. [`bloodborne-native/bloodborne-mac/docs/ROADMAP.md`](https://github.com/bloodborne-native/bloodborne-mac/blob/main/docs/ROADMAP.md) distinguishes 10 separate translation layers rather than presenting AOT coverage as whole-game native completion. Important donor lesson: isolate **full-game import/call closure**, **OS system APIs**, **GPU draw boundary**, **texture objects/memory**, **actual native startup** and **gameplay replay** as separately testable acceptance gates.
5. [`bloodborne-native/bloodborne-recomp` PR #12](https://github.com/bloodborne-native/bloodborne-recomp/pull/12) optimized register spill/reload across calls; PR #14 optimizes translation-cache invalidation. These are valuable optimizations and test methodology, but translator-specific improvements alone are not enough to meet our no-interpreter-runtime requirement.
6. [`SoulsFormatsNEXT` PR #55](https://github.com/soulsmods/SoulsFormatsNEXT/pull/55) allows multiple position/normal semantic layers needed for cloth and alternate meshes; PR #56 allows FLVER reading without eagerly instantiating every vertex. Our V371/V375 supported layouts remain deliberately narrow.
7. [`Paleblood` PR #655](https://github.com/Yharnam-Hunters/Paleblood/pull/655) identifies hardware tessellation/geometry stages and rejects unsupported draws rather than silently interpreting them as simple triangles. Preserve similarly strict contracts across native GPUs.
8. Runtime donor family: [`deadinside28/bloodborne_pc`](https://github.com/deadinside28/bloodborne_pc), [`droogie/bbhost`](https://github.com/droogie/bbhost), [`shadps4-emu/shadPS4`](https://github.com/shadps4-emu/shadPS4), [`GPUOpen D3D12MemoryAllocator`](https://github.com/GPUOpen-LibrariesAndSDKs/D3D12MemoryAllocator), [`VulkanMemoryAllocator`](https://github.com/GPUOpen-LibrariesAndSDKs/VulkanMemoryAllocator), [`Valve Proton`](https://github.com/ValveSoftware/Proton), [`DXVK`](https://github.com/doitsujin/dxvk) and [`VKD3D-Proton`](https://github.com/HansKristian-Work/vkd3d-proton) remain references and optional compatibility routes, not the target game's mandatory native runtime.

A targeted review can broaden over time through GitHub search, forks, PRs, branches, documents, and private Drive resources. No truthful claim is made to have enumerated all GitHub or imported all upstream work. Do not copy private game bytes or third-party source without rights/provenance checks. Performance gains must be measured on actual hardware and representative scenes.

## Critical path and next iterations

**P0 whole-game executable**: An independently buildable Windows/Linux native entrypoint, generated only offline from the user's legally owned 1.09 assets, with *zero runtime PS4 executable mapping/patching*, *zero translator/interpreter fallback*, and an auditable import-closure manifest mapping every reached original OS/API call to native platform implementations. Tests must replay representative gameplay (including gameplay state changes, exception/longjmp semantics, threads, graphics, audio, save format), then full offline playthrough plus DLC/chalices; any missing call should fail visibly rather than running guest code. Gameplay code coverage, imports and GPU draw boundary need quantified per-build acceptance criteria.

**P0/P1 GPU scene**: Map actual private-owner skeleton indices and bone palettes through genuine mesh LOD/material associations to vertex skin matrices on Vulkan/D3D12; use world transforms and inverse bind pose with verified matrix ordering; test bone attachment positions, bind pose, animated frame, degenerate/strip topology, and multi-mesh/LOD draw batches on physical GPUs. V375 is only local/world bind matrices — no inverse-binds or GPU skinning yet.

**P1 native streaming/performance**: Integrate DCX/BND4→FLVER/HKX/TPF file IO into bounded async streaming, persistent D3D12/Vulkan staging and residency budgets, priority/cancel-safe pipeline, shader warmup and p95/p99 frame-time tracking. Restore-by-fence, GPU device loss, texture memory, graphics crashes and stutters are release gates.

**P2 after correct offline base**: Native keyboard+mouse/action chords, controller mapping and HUD glyphs, configurable jump, manual NG+, QoL, accessibility, mods, DLSS/FSR/XeSS/Reflex (device/SDK dependent), window/HDR/VRR; then LAN/localhost/dedicated servers, matchmaking, session rejoin, latency/jitter/loss metrics and full coop/invasions. This full feature list is tracked in `V366_PROTON_NATIVE_GPU_RING_AND_ULTIMATE_ROADMAP.md`.

**No production deployment, PR auto-merge, save modification, private asset publication, game-asset redistribution or completed-native-game claim.**
