# Bloodborne Ultimate Native PC — V378 x64, arbitrary resolution and strict AOT readiness

Date: 2026-11-12. Base: `feature/native-v377-aot-closure-fixed60-20261112`. Native Windows/Linux target. All concrete user requests below are backlog/acceptance requirements unless explicitly labeled tested.

## Important 64-bit clarification

The **original PS4 game executable is already x86-64 ELF64**, not a 32-bit x86 title: our existing private original 1.09 preflight `private_original_preflight_v212.py` checks little-endian ELF64 and AMD64 e_machine 62. The desired deliverables are independent **64-bit Windows PE32+ x86-64** and **64-bit Linux ELF64 x86-64** game processes that do **not** load original PS4 EBOOT/SELF/ELF or interpret guest code at runtime. "Make the game 64-bit" means a proper native host OS, game entrypoint, 64-bit GPU/streaming/address-space handling, complete native API imports and actual game logic, not a false conversion from PS4 x86 32-bit. Keep explicitly serialized asset fields and game/network IDs at their original defined sizes; do not indiscriminately convert all 32-bit offsets or file-record fields to 64-bit.

The V377 static preflight already checks native Win64 PE32+ and Linux ELF64 synthetic executable formats. Those synthetic EXEs are **not Bloodborne**, and their existence does not prove complete original-game native AOT or fully independent game startup.

## V378 implemented source-only display/layout contract

Files: `native_display_contract_v378.{h,c}`, `test_native_display_contract_v378.c`.

- Native x86-64 ABI static assertions for pointer and uint64 sizes; explicit AMD64 CPU architecture check, not merely `sizeof(void*)==8` on unrelated processors.
- Integer-checked output dimensions and render-scale 50–200%, separately bounded by **caller-supplied enumerated OS mode and actual GPU texture/VRAM limits**. In V378, OS mode discovery, VRAM residency, swapchain and presentation are **not implemented**; caps are test-supplied.
- Input 16:9 vertical FOV is retained when the image extends horizontally or vertically; horizontal FOV is recomputed from the aspect ratio. The game world uses full output aspect (no fake 16:9 stretch). Real engine camera/FOV and projection integration still pending.
- The 16:9 HUD/cutscene fit rectangle is centered *within* any output aspect; optional safe inset keeps icons, subtitles and prompts readable on 21:9, 32:9, 4:3 and portrait. This is geometry only: actual HUD glyphs, UI text engine, backgrounds, camera, cutscene framing and subtitle rules remain to implement. Full-screen world may display more horizontal content; pre-rendered cutscenes should fit rather than silently crop.
- A GPU surface is reusable only when **both width AND height**, sample count, format, usage and colorspace match. Never reuse based on one matching dimension or resize without waiting for in-flight GPU usage to retire. The implementation is a CPU-side allocation-key predicate, not a live GPU swapchain manager.
- Pure C11, no graphics driver, no original game files, no dynamic allocation, fail closed without partially updating the caller's prior display plan.

Public synthetic tests cover **640×480, 1280×720, 1920×1080, 2560×1440, 3840×2160, 7680×4320, 2560×1600, 1920×1200, 2560×1080, 3440×1440, 5120×2160, 3840×1600, 5120×1440, 7680×2160, 1080×1920, 4096×2160 and 7680×3200**, plus safe 50% and 150% rendering scales; deliberately invalid output sizes, NaN FOV, over-budget render targets and unsafe partial-size GPU attachment reuse. These tests **do not mean all monitors/GPUs can produce all resolutions**, or that the original game has a working ultrawide camera/UI today. Avoid claims of universal GPU capability; enumerate actual OS/GPU/swapchain modes and guard HDR/VRR features before exposing them.

## V378 implemented private-safe AOT gap inventory

`native_aot_closure_dashboard_v378.py` consumes only preexisting **aggregate** V207 scanner→AOT registration statistics and V287 private COFF external-symbol closure counts. It rejects inconsistent counts, malformed/oversized or symlinked input reports, and prints only whitelisted numeric totals and blocker category names. It never prints names, addresses, original objects, source paths, binary hashes or game executable bytes. `test_native_aot_closure_dashboard_v378.py` ensures these secrets remain absent even if a JSON input maliciously contains extra keys.

The report **never** promotes a game to native-ready based on scanner coverage or COFF symbol closure alone. Even if synthetic test counts reach 100% and zero unresolved imports, `strict_native_game_ready=false` and mandatory blockers remain: independent original game PE/ELF linker + startup, zero guest executable/interpreter at runtime, complete offline gameplay. The report is an actionable P0 blocker dashboard, not a replacement for private original v1.09 AOT, native OS imports, code/physics/audio/AI/server functionality or live game proofs.

## Mandatory Ultimate feature contract and priorities

**P0: Actually playable native game.** Windows AMD64 PE/Linux AMD64 ELF executables, true game entrypoints, no runtime original EBOOT/SELF/ELF or guest CPU/GPU translator, complete original game logic, AI, animation, events, NPCs/bosses, physics, cinematics, audio, saves, NG+, chalices, DLC and offline validation. The real proprietary original source is user-owned and only processed privately offline; no game code/assets in public source/CI.

**P0: Time and simulation invariance.** User target is **60 Hz fixed-step simulation** and independent display 30/60/120/240/unlimited (custom 90/144/165/360 optional), but actual Bloodborne original 30Hz effects and physics/cutscene/scripts/combat i-frames/AI may require 30Hz compatibility or deeper semantic work. V377 has only a synthetic 60Hz clock prototype, not actual game timing. Never tie simulation, damage, save times, enemy AI, network tick or movement to rendered FPS. Test 10+ minutes combat, Rom's lake wakes, elevators, cloth, hit windows, camera, cutscenes, interactions and server-coop timing across cap changes; validate deterministic sim under jitters and missed deadlines.

**P1: Resolutions and graphics correctness.** Native resolution enumeration (all OS-exposed display modes within GPU budget), 4:3/16:9/16:10/21:9/32:9 and mixed portrait/landscape monitor layouts, high DPI/scaling, windowed/borderless/exclusive where supported, smooth live resize, fullscreen switching, non-cropped ultrawide world view and properly fitted menus/cutscenes/HUD, independent internal/output resolution for dynamic scaling and reconstruction. Per-resolution target recreation must retire old resources at real GPU fences; single-dimension matches must not share surfaces. Support PC field of view/camera where physically valid and content-safe; test culling, shadow maps, postprocessing, SSR, particle positions, video overlays, subtitle placement, HUD prompts, boss health, target lock, screenshot capture, controller glyphs and multiplayer nameplates on arbitrary aspect ratios. Expose HDR only with verified color pipeline, 10-bit formats, color management and device capabilities; VRR only where OS/display supports it.

**P1: Performance, latency, stability.** Windows D3D12 and Linux native Vulkan with optional Windows Vulkan; async file read→DCX/BND/FLVER→textures/animations→priority residency; memory budgets, pooling, cancellation, eviction, no vertex-cache explosions, robust validation and loss/recovery; shader/PSO warmup and versioned GPU+driver+settings cache, background compilation, transparent progress and safe invalidation. Monitor p50/p95/p99/p99.9 frame-time, shader hitches, GPU/CPU queue depth, VRAM and RSS, crashes, hangs, long-session leaks, file streaming pressure, device loss, alt-tab/multimonitor/resize/dpi switch, 30/60/120/240/unlimited physics parity. Never claim zero stutter or maximal FPS from software-GPU smoke tests alone. Opt-in, hardware/SDK/driver-approved FSR/DLSS/XeSS, Reflex/XeLL where available, dynamic resolution, AA/sharpening and frame generation; no fabricated generic support and no proprietary SDK files copied without permission.

**P2: Full PC controls and remaster/QoL.** Native raw KBM, configurable combinations such as Shift+key/Ctrl+key and gamepad two-button chords, tap/hold/double-tap with conflict handling, dedicated remappable jump (L3/B/Circle/keyboard), mapping of movement/camera lock/sprint/ranged/etc, keyboard/gamepad glyphs and live device hot-swap, PlayStation/Xbox/Nintendo/Steam Input/HID, deadzone, gyro, rumble where supported, mouse smoothing/acceleration options, colorblind/subtitles/accessibility and HUD safe scaling. Manual NG+ selection with safe backup and validation; per-character settings, fast startup, editable camera, save backups, opt-in mods and correct achievements after real offline game completion.

**P3: Online client/server/launcher and releases.** Matchmaking, co-op/invasions, quick match, invites, friend/password/LAN/localhost/private/dedicated, region/server selection, ping/jitter/loss, progress and world state sync, deterministic tick, prediction/reconciliation, secure session authentication, NAT traversal with relay fallback, bounded packet/CPU processing, interest management, desync detection, host migration when possible, reconnect and failure handling. Independent transport benchmark of median/p95/p99 join time, packet loss, server load and RTT; impossible to promise zero geographical network latency. Minimal idle CPU/memory, dedicated deployment health check, no secrets in client, safe schema versioning, rollback, logs redaction and crash statistics. Modern launcher with signed content manifests, atomic/resumable/delta updates, verification, repair, rollback, channel selection/test badges, automatic driver/preflight diagnostics, integrity checks and no live-server change without explicit gate. Discord RPC formatting/visibility/chat/HUD toggles tracked in existing BBSC Ultimate project, separately from native executable milestones.

**P4: Evidence and release standard.** Cross-compiler Linux/Windows CI, real AMD/NVIDIA/Intel hardware and software-driver tests, offline original-game test harness only on owner-owned licensed data, playthrough+all DLC/chalice/save migration plus 24h soak, video-mode matrix, render/physics/online checks and reproducible telemetry. Deliver release only after *real independent game startup* with guest code absent under runtime file tracing, not from green data-parser or synthetic rasterization tests. Preserve the existing playable BBPort and BBSC Ultimate branches independently until proven compatible.
