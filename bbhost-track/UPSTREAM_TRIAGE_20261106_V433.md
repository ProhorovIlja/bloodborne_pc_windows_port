# Upstream triage 2026-11-06: V433 BBHost + YT GameLink and NAT

Scope: real user-selected two-track Bloodborne project. This is *candidate triage*, not evidence of a working five-PC coop. No production Fornex, no game assets in GitHub.

## Inspected sources and branches

- Original released **YT 1.4.0** at `efa0ad265d840d9195e55db2e3216f46f7daedd0`: `server/coop/game_link.h` blob `5029581251bfe5decf562c19a10bdd079150cdad`; `server/coop/packet_routes.h` blob `f732c87cd0a030751f5ed23dfa225e98bb8ffc5c`. This remains the **actual compatibility oracle**; never substitute invented public GameLink JSON. The original sender uses `GameFrame` seq/ack/instance. Reliable dropped entries become **channel 68 + length 0** and retain seq; already-tombstoned entries are kept without counting another refusal. Per-channel `NativeChannelPolicy` is insufficient: co-op, invasions, maps, enemy part, 0x15/0x16/0x17 special cases all matter. **V433** models and checks all of these exhaustively *against the compiled original source*, over channels 0..68/255, four map states per side, all three enemy-owner roles and both visitor directions. No production route authorization granted.
- Original YT GameLinkPeer defaults to **1200-byte target frames** but permits a large single packet as its own frame; has ACK/sequence, resend backoff 150 -> 2000 ms, quiet fence, per-peer instance/restart and out-of-order byte budget. Do not mix it with BBHost kernel P2P datagram framing: these are distinct layers. Original server currently relays gameplay, no direct authenticated guest-to-guest UDP proven.
- YT `fix/launcher-3d-map-game-folder` is 1 commit ahead of v1.4.0, matches open PR **#537** and should be considered in the **launcher phase**. `native-netcode-research` (1125 behind), `game-link-resend-backoff` (913 behind), `invasions-game` (357 behind), and `fix/coop-game-2026-11-01` (131 behind) are not substitutes for current source without a bounded diff review.
- YT open PR **#524** fixes Travel Together lock inversion, tests include controlled Mac gameplay but no Windows validation. Valuable once gameplay hooks work, not permission to alter the pinned server by itself. PR **#518** corrects website five-player copy, not co-op engine. Rejoin PRs and shadNet upstream remain on the watch list.
- **BBHost** pinned actual plugin build is `b0098e04b889e2e70b4af84be1ce809d7af3ff95c5f` (v0.2.24). New `bdc5cdf` (v0.2.26/master) `src/hle/net.cpp` adds `chunk_split` of native PS4 P2P datagrams into whole channel chunks, target **1200 bytes** to avoid Internet IP fragmentation, and `tests/net_p2p_test.cpp`. Comparison with pinned BBHost yields **45 later commits**, including large renderer/workload changes; do not wholesale merge for a single network fix. First isolate, adapt, and test this change against pinned BBHost in a candidate branch using real multi-OS tests. Pinned NetSync GameLink is a separate guest hook.
- BBHost open draft PR **#213** for v0.2.27 improves Windows uncapped/8 GiB GPU cases, and changes default scheduling and buffer allocation. Its own description still asks for Windows tester runs. Do not advertise performance gains without 1%-low, VRAM, CPU, draw and GPU failure measurements; evaluate on separate performance track.
- **NightwatchCoop** `engine/gpu/shim/net/party_udp.h`, `engine/gpu/shim/party/party_nat.h` model direct NAT-probe/ack with host-relay fallback. Relay data is framed by an independent UDP `0xfb` token format. Useful architecture reference **only**: neither those tokens nor a public STUN response authenticate a YT original server room/peer/owner. Do not copy the packet protocol or trust peer endpoint without the correct per-peer crypto binding.
- **CLSAMG22/BBSC** gameplay PR **#38** DBNO revive and PR **#22** respawn/risk guard remain candidates for a later gameplay compatibility pass; test separately with YT's death/DBNO group semantics.
- The separate **native eboot-free Windows port** task is not superseded by BBHost or YT using native PS4 game code. Shared tools and verified gameplay rules can help it, but current source/CI does not constitute an independent native PC binary.

## Promotion criteria

1. Keep original YT `packet_routes.h` and `game_link.h` as source oracle, including invader-specific channel drop and **reliable tombstone sequence** behavior.
2. Add server-authenticated per-peer path identity with non-replayable room/instance/map/owner binding; validate actual guest OnlineID against live server TeamMember plus verified peer endpoint. **V431/V432 do not provide the final authority.**
3. Prove direct BBHost P2P STUN/NAT/relay transport on authenticated peers; fallback should be explicit and never misrepresent relay as direct. Integrate large-P2P chunk splitting only for correct packet format and expiry, not for arbitrary YT encryption frames.
4. Complete game-thread inbound queue delivery and safe original handler continuation. Test with 2..5 real game clients across relayed and NAT cases; record median/p95 latency, peak bandwidth/CPU, disconnect/rejoin, world/loot/owner/invasion correctness, 1%-low FPS and memory before release.
5. No Fornex, website or launcher deployment until server-client-client compatibility is demonstrated and approved; test builds carry a `TEST` ribbon only.
