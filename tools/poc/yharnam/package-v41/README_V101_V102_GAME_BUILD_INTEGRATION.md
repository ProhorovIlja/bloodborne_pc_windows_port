# V101 + V102: actual native Windows game source integration, fast-fail compiler

2026-10-26. DRAFT PR20. No live Fornex, master, account, save, network or firewall change.

V97 Doll flag 6700, V98 corpse-hit counter lamp respawn, and V99 resurrected guests regain boss AI targets originally passed independent native source C++ tests on DRAFT PR17. PR20 is a different branch and actually builds the native Windows EXE. Its older unified source composer did NOT include those original game source changes, so CI passing on PR17 did not mean the binary contained them.

V101 copies the exact three reviewed upstream game patch scripts from PR17 into PR20, then applies them in order (V97 -> V98 -> V99) AFTER the original PR20 source composer and BEFORE compiling actual native bbnet game units. stage_gameplay_v101.py requires Git HEAD 77e350743a7cb4524cfcc1782fb6e3af64e25b15, refuses missing/symlinked source, verifies all seven original game files, performs all transformations before writing any, checks the original native GPU CMake includes party.cpp, party_death.cpp, flags_store.cpp, re.cpp, and writes a per-file SHA256 manifest at bbport/out/shyt-v101-gameplay-source.json.

A first actual Windows full build with V101 failed at the strict Doll source anchor. The separate post-composer audit showed the original PR20 composer did NOT overlay bloodborne_flags.h but DID overlay party_death.cpp and re_internal.h from its older work. The actual problem is Windows Git's CRLF checkout vs GitHub raw LF exact source pins: V101 normalizes ONLY fully uniform CRLF to LF, rejects mixed line endings or stray CR, and then applies exact source-checked transforms. No fuzzy matching or replacement of unknown game code. Windows and Ubuntu original source chain tests also require CRLF output to be byte-identical to LF output, and refuse double-application or a missing input.

The independent audit CI shyt-v101-postcompose-gameplay-audit.yml verifies the original composer output. Actual integration CI shyt-v101-native-original-gameplay.yml fetches the seven original immutable source files and composes all V97-V99 on Windows and Ubuntu. The real Windows game CI shyt-v63-native-game-candidate.yml must still fully compile/link, package and be played before this is considered a playable build.

V102 fixes repeated GitHub full build 165-minute timeouts after genuine compiler failures. In original bbport/build.sh, Ninja redirects to out/gpu-build.log; the heartbeat used to print the same Sirit std::abort or FidelityFX _countof compiler error every thirty seconds until the step timeout. The shared native Windows workflow now inspects the real Ninja log for unmistakable failure records including FAILED:, fatal error:, : error:, ninja: build stopped, or MSVC error Cxxxx and aborts on detection. Includes sanity checks for fatal matching and harmless warnings. The CI error artifact remains internal, not published as a working release.
