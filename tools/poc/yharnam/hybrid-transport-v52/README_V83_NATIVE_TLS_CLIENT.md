# V83: actual native OpenSSL/LibreSSL TLS 1.3 client to the existing single Qt shadNet server

**Verified source milestone, development-only. Not a native public internet-ready client, nor live Direct P2P.**

- New `sh_native_tls_local_client.hpp` is a non-Qt C++20 client using the OpenSSL/LibreSSL SSL API already available to the pinned game through the original `Cpp_Httplib` dependency. It connects **only 127.0.0.1**, to an operator-selected local test port. There is no hostname resolver, proxy, public server endpoint or new gameplay socket.
- Creates real TLS 1.3 with mandatory server CA verification, **127.0.0.1 X.509 IP SAN** verification, and client certificate/private key matching the server's operator-pinned V79 leaf. It will neither ignore certificate errors nor downgrade to plaintext, TLS 1.2 or plain SHLK.
- Sends `YT-P2P/V80 BEGIN\n`, reads one exact bounded V80 256-bit ephemeral application key; `YT-P2P/V81 OFFER\n` then reads one bounded authentic SHG1 sealed grant from the same authenticated TLS connection. Grants are passed directly to the SAME portable V82 `NativeSealedGrantInbox`, bound to the caller's trusted recipient/peer account tokens, current V77 epoch and world revision. Any wrong/missing cert, stale game world, malformed line, expired or replayed grant or changed consent fails closed and erases the secret.
- Important fixed bug: a grant is minted AFTER TLS starts. Validation must use actual **message receipt time**, not the initial Request() timestamp, otherwise the authenticated grant is wrongly rejected as issued in the future. This was reproduced and repaired in commit `e71f4de028bad4ed4c85e060b107921af79819fd`.
- `patch_native_tls_local_client.py` puts an explicitly callable, **compile-time disabled by default** `TryLocalTlsOfferForTest` in the ORIGINAL pinned game's `P2PTransport`, guarded by `SHYT_ENABLE_TEST_LOCAL_MTLS` default OFF in `emulator/CMakeLists.txt`. It reuses `native_grant_inbox` and its existing mutex but **has NO runtime call site, no automatic connection, no Direct TX/RX Arm**. This composes via `tools/poc/yharnam/unified-v9/compose_sources.py`. No separate game server or daemon.
- Real integration regression `test_native_tls_local_client_qt.cpp` drives the **native OpenSSL/LibreSSL TLS client (not Qt)** in a worker against the existing Qt V78-V81 mTLS server, with throwaway CA and certs generated solely in CI. Verifies accepted V81 cipher offer, native V82 recipient proof, wrong CA refusal, stale recipient world, peer opt-out, absent game state and repeated TLS connection serial refusal. This tests real network TLS over loopback, NOT a production remote client.
- **Both GitHub CI jobs passed:** https://github.com/ProhorovIlja/bloodborne_pc_windows_port/actions/runs/40228987556 . Compiled the full pinned Qt server native C++ source entry with V78–V83 overlay and ran V78–V83 actual Qt/OpenSSL suite.
- Still needed: true authenticated public native TLS control path, user account/certificate enrollment/revocation, full-width collision-resistant signed account IDs (V75 offer still truncates to 64-bit), server-client room discovery, signed mutual opt-in, persistent cross-connection replay defense, encrypted game datagrams, NAT candidate exchange and 3 signed reverse probes using same UDP socket, key-direction pairing, actual game Sender/Receiver Arm and reliable GameLink ACK/seq handover. As of V83 **all game traffic remains shadNet relay**, no measured load savings and no proven two-PC Direct.
- The live Fornex CLS Friends unit, database/account state, firewall, ports, and production credentials are not touched. The separate Windows renderer/game loader full build is independent and has not yet yielded a verified playable ZIP.
