# V90: two real authenticated native TLS clients receive one reciprocal SHG2 pair

**Development-only, original Yharnam Together / single shadNet Qt server. Direct gameplay UDP remains OFF.** This is NOT yet a feature in the shipping Bloodborne launcher or a remote Internet listener.

## New concrete implementation

- `sh_p2p_pair_lease_v90.hpp`: Qt-side, **single-use**, 10-second server-owned reciprocal pair lease. It starts only when a trusted in-process Qt server caller supplies both game-accepted accounts and the original `LinkServer`-backed `P2PLocalOfferScope` resolver. It snapshots and verifies both directions twice at creation, then **rechecks both** on every mTLS recipient delivery. Each half has the same CSPRNG pair binding/master but the recipient's own authenticated account and session epoch, peer endpoint and the correct crossed pair identities. Any missing session, opt-out, changed world, link epoch/endpoint, premature/late request, unexpected recipient or repeated request fails closed and zeroizes the server pair secret. After both halves are legitimately issued, the server destroys its remaining copy **immediately**.
- `sh_p2p_tls_listener.hpp`: adds privileged local-only `ConfigureLocalReciprocalPairV90` (before listen) and an explicit `YT-P2P/V90 OFFER\n` request over the existing 127.0.0.1-only **TLS 1.3 mutual-cert** Qt listener, with live fingerprint->account/epoch verification on that very session. Request packets never carry account, peer, room, endpoint or consent claims. No extra service/port.
- `sh_p2p_tls_key_session.hpp`: seals exactly one already-authorized pair half under that TLS session's independent V80 AES-256-GCM wrapping key, refusing an account mismatch, changed epoch, second sealed grant or stale lease. Response deliberately keeps the known **`YT-P2P/V84 OFFER`** SHG2 ciphertext framing so existing V84 native sealed inbox can parse it. The original V85 one-sided command remains explicitly **incompatible** with the coordinated V90 handshake.
- `sh_native_tls_local_client_v90.hpp`: source-only, non-Qt OpenSSL/LibreSSL native TLS 1.3 client based on audited V85, now requesting V90 pairing. The same X.509 CA+127.0.0.1 IP SAN+client cert checks, current game-identity refresh and V84 unarmed inbox remain mandatory.
- `test_real_mtls_pair_v90.cpp`: uses the real kernel TCP loopback, one Qt server, an ephemeral CI-only CA, **two different certificate-pinned native client identities and two different mTLS sessions**. Both independently receive offers for the same pair master; derived NAT probe keys for A→B and B→A match the opposite receiver but differ from the reverse direction and from the future gameplay key. Third request/replay fails. No real Direct game UDP socket is accessed.
- `test_pair_lease_v90.cpp`: adversarial authority tests for opposite recipient/peer, stale epochs, world changes, opt-out, endpoint mismatch, wrong recipient, order reversal, replay, timestamp expiry and changed server state during lease creation.

## Hard boundary between source/test and playable Direct P2P

This still uses **an intentionally local-only test listener** and a trusted setup callback. Production account enrollment, certificate issuance/rotation/revocation, rate limiting, logging without secrets, remote TLS endpoint discovery and a durable, server-authorized **both-halves-ready ACK** are NOT implemented. A previously delivered half cannot be remotely revoked instantly until native gameplay routing enforces live confirmation. The original native game P2PTransport has no automatic V90 caller and is not using the V90 lease in live gameplay.

Before Direct: add authenticated pair-ACK and signed challenge/response NAT probes on the **existing native game UDP socket**, AEAD for every Direct game datagram, verify actual reliable GameLink ACK/seq migration as one route, expire/revoke/fail back to server atomically, and run genuine two-machine Windows + CGNAT + 200-player stress tests. No production Fornex, CLS Friends server, firewall, database, saves, `master` or public game configurations have been modified.
