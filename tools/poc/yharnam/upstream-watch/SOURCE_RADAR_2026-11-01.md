## Review queue: specific external changes worth extracting

1. **P0: Co-op invader race.** YT [#475](https://github.com/lKaniel/bloodborne-server/pull/475), Oct 31 draft: guest can incorrectly exit when invader is counted as joined ~5 s before it enters the actual session. Fix gates subtraction on the invader's confirmed membership. **ALREADY IMPLEMENTED IN OUR DRAFT PR #73 (V177)** against the older YT1.3.0 pinned source, with extra invader-identity cache invalidation and synthetic five-hunter C++ checks. Last V177 CI was green on head `440acc290b` (GitHub Actions run 41227870434). **Do not duplicate this fix**: next task is to rebase/review its exact source edits onto YT1.3.1, run real multi-PC 5-seat/invasion sessions and check that the 500 ms cache behavior survives upstream changes. Upstream reported 2/4 rig passes, with invader loading stalls in the other two; synthetic C++ success is not gameplay proof.
2. **P0: Multi-team isolation and invasion scenarios.** YT [#474](https://github.com/lKaniel/bloodborne-server/pull/474) draft adds 4-game-slot isolated-team, team-switch and solo invasion rig cases, plus per-run `Invasions` toggles. Adapt **test architecture** to five total players, DBNO/wipe/ghost state, host migration and per-team world flags. A rig result is not a game-session result.
3. **P0: Linux/Windows source portability.** YT [#450](https://github.com/lKaniel/bloodborne-server/pull/450) includes native Linux Qt server and client work, system-protobuf fallback and case-insensitive EMEVD patch resolution. Upstream author describes one Linux/Windows cooperative run. Validate with the YT 1.3.1 protocol; do not import untested Linux guest hooks into Win64.
4. **P1: GOTY fingerprint caution.** Supermedo [#147](https://github.com/Supermedo/bloodborne_pc/pull/147) draft: CUSA03173 GOTY can report `APP_VER 01.00` while carrying 1.09 executable code. Existing patch verifier compared one old fingerprint against group-specific fingerprints, disabling patches. If adopting, use **whole-image known hashes and per-group exact-byte tests**, not a blind version-string override. Never publish user's decrypted game.
5. **P1: GPU resource lifetime.** Supermedo [#144](https://github.com/Supermedo/bloodborne_pc/pull/144) source-reviewed optional motion-vector cache (4 live reusable targets, max 2 pending/128 MiB, wait after last GPU use), with focused CPU tests but no upscaler gameplay proof. Reproduce fences, retirement and VRAM budget in the chosen *native* graphics architecture before adapting.
6. **P1: Open-party security.** visy [#26](https://github.com/visy/bloodborne_pc_windows_port/pull/26) merged, adds default-off LAN/VPN-subnet passwordless open joins. Upstream warns that its open-party encryption does not protect against other peers on the same network. Our YT open-team join filters must bind invited friend/host authorization and **not** silently enable public joins; no replacement of auth/wire.
7. **P1: Host-selected seat count.** visy [#24](https://github.com/visy/bloodborne_pc_windows_port/pull/24) merged: guest accepts host-selected max; game's patch signatures must not vary by the joiner's local cap. Review for YT five-seat semantics and the specific mix of co-op/invaders. visy's packet format is unrelated.

## Validation plan and evidence policy

- **Gate A: source fidelity.** Confirm source commit and license, check strict version and opcode/data-layout compatibility against local Bloodborne 1.09 and DS3. Original files *stay private*. Reusable public tests use synthetic invented binary data only.
- **Gate B: real native code.** Verify guest CPU layout and register/lazy-flags/stack, true Zydis hashes for original unchanged functions, mapped memory, real Win64 DLL dispatch and rollback. Full native renderer/audio/input/OS APIs are independent work. No PS4 eboot execution/PS4 compatibility layer in the *target* finished program.
- **Gate C: co-op behavior.** Five seats total across 5+0, 4+1, 3+2 and 2+3 (subject to role rules); invitations, friends, privacy, boss invasions (future), host migration, DBNO, spectator camera, cutscenes, bosses, chalices, events, NPC rewards, world ownership and safe disconnects. Multi-PC gameplay needed before claims of correctness.
- **Gate D: P2P and server.** Server handles only authentication, discovery/control and authoritative invariants; signed/encrypted peer-to-peer data where reachable, measured TURN/relay fallback when not. Measure end-to-end packet delivery and latency under >=200 concurrent players without conflating load-generator success and gameplay.
- **Gate E: launcher and distribution.** Signed/hashed staged downloads, atomic replace/rollback, migration of existing saves/settings/mods, diagnosis of crashes/Vulkan/runtime/firewall, repair without data loss, Windows trust store, accessible keyboard/controller UX and opt-in Discord Rich Presence privacy.
