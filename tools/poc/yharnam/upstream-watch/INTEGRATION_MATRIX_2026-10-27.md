Reviewed **2026-10-27** from upstream GitHub PRs, release notes and verified repository commit listings. This file deliberately separates **verified upstream behavior** from untested usefulness to our fork. All changes remain candidates until isolated source reviews, built tests and two-PC gameplay evidence say otherwise.

## Our non-negotiable baseline

- **Our clean native YT v1.3.0 staging:** [draft PR 21](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/21), fixed upstream commit `0645740a33ae21c56df3b4a0d9777086dbca6053`. Do not mistake staging server-only code for a ready-to-play, fully integrated native Windows client.
- **Protocol authority:** Yharnam Together only. The authentication, trusted sign-in, party/world coordination, invasive features and anything security-sensitive remain under authorized server authority; desirable peer game frames eventually go authenticated Direct P2P with server relay fallback **only after 2-PC security and functional QA**. Visy's own serverless-party protocol, Supermedo's shadNet, Linux shadPS4 v0.20 or BBSC transports are not drop-in interchangeable with YT. No bridge by blindly replacing headers or forging identities.
- **Production isolation:** never touch live Fornex, CLS Friends, real identities/accounts, player saves, firewall or `master`; use disposable upstream checkout + pin/manifest, DRAFT PR and test evidence.

## Safe workflow to graduate a feature

1. Record original repo, release/tag, **exact source commit and file paths**, license, target CUSA/update and platform. Inspect *all code paths* touched; don't mix incompatible variant implementations.
2. Put candidate into an **isolated diff against a known YT v1.3.0 native baseline**, not old V3-V123 shadPS4 patches. Split renderer vs launcher vs gameplay vs server and make rollback atomic.
3. Unit & integration: launcher/settings, actual native Qt/SQLite/tests, game runtime, save restore. 4-person sign-in and team joining **must** work before 32/64/100 stress stages. Unhealthy p99 and packet loss = reject even if compilation and CTest pass.
4. For online behavior, YT authenticated team authority and compatible versioned client/server release remain mandatory, followed by two physical PC tests of Direct P2P with NAT/relay fallback and strong privacy/security.
5. Only after reproducibility, gameplay QA and independent proof: promote to release candidate. Never automatically merge changes that upstream authors themselves keep in open PRs.

**Current server evidence:** parent [PR #21](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/21) unhealthy above 32 synthetic localhost players. [PR #22](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/22) UDP fairness experiment caused 0 gameplay and was closed. [PR #23](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/23) non-hosted lobby-state dedupe builds/tests and helps plausible control-plane overhead but still fails 64-player healthy p99. [PR #24](https://github.com/ProhorovIlja/bloodborne_pc_windows_port/pull/24) instruments wire Data/Coop/RPC bytes in disposable server and must not be called a performance fix until results exist.

## Automated drift watcher scope

`python tools/poc/yharnam/upstream-watch/watch.py --output <destination>` uses **only public GitHub read-only requests**: per source `commits/HEAD` and `releases/latest` plus pinned YT and Windows native fork PR metadata. Failures are reported as **unknown**, never silently passed. It creates `upstreams.json` and `UPSTREAMS.md` for human review without downloads, builds, changes to source, GitHub writes or touching game servers.

`.github/workflows/shyt-crossfork-upstream-watch.yml` runs offline tests and creates a report artifact on the candidate PR. Its daily schedule **does not activate while this workflow exists only in a DRAFT PR**; it would begin *only if this watcher workflow were deliberately reviewed and merged to the default branch*. Do not claim recurring surveillance until that happens, and do not merge without explicit authorization to modify master.
